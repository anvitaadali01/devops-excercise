# Exercise 8: Hello World Jenkins Job

> The requested notes file, `8-Jenkins-Hello-World-Job.md`, was not present in the workspace or tracked repository when this exercise was prepared. This guide follows the steps and requirements supplied in the task.

## Objective

Create and run a Jenkins **Freestyle project** that checks out the existing GitHub repository and executes a small Bash script from the `Ex 8` directory. The job demonstrates source checkout, a build step, and verification through the Jenkins console log. The Freestyle project is the required workflow; this exercise does not add a Pipeline job or Jenkinsfile.

## The shell script

`hello-world.sh` contains the lab command:

```bash
#!/bin/bash
echo "Hello, Jenkins!"
```

The shebang selects Bash on a compatible Linux agent, and `echo` prints the expected greeting. When invoking the script directly as `./hello-world.sh` on Linux, set its executable bit with `chmod +x "Ex 8/hello-world.sh"`. The Freestyle build instructions use `bash hello-world.sh`, which invokes the interpreter explicitly and does not require the executable bit. Windows PowerShell does not use Linux `chmod` permissions in the same way; run the build step in Jenkins' Linux/Unix shell environment, not as a PowerShell command.

## Jenkins prerequisites and status check

You need a reachable Jenkins instance at `http://localhost:8080/`, the Git plugin, a Jenkins build environment with Bash and Git, and network access to the repository. For a Jenkins agent running in Docker on Windows, **Execute shell** runs inside the Jenkins/agent environment, not in Windows PowerShell. That environment needs the shell and Git checkout support.

Before installing or starting Jenkins, inspect whether a container with that name already exists:

```powershell
docker ps -a --filter "name=^/jenkins$"
```

If it is running, keep using that instance. If it exists but is stopped, inspect it and start that same instance if appropriate:

```powershell
docker start jenkins
docker ps -a
```

Do not remove an existing Jenkins container or its data to follow this lab. If no `jenkins` container exists and Docker Desktop is running Linux containers, install Jenkins with the notes' command:

```powershell
docker run -d --name jenkins -p 8080:8080 -p 50000:50000 jenkins/jenkins:lts
docker ps -a
```

Open <http://localhost:8080/>. If setup is not complete, retrieve the generated initial administrator password from the host:

```powershell
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

The interactive equivalent is:

```powershell
docker exec -it jenkins bash
cat /var/jenkins_home/secrets/initialAdminPassword
exit
```

Use the password generated by your own Jenkins instance. Keep it private and out of this repository, console screenshots, and source files. Complete the initial setup wizard and install the suggested plugins, including Git if it is not already installed.

## Configure the Freestyle project

The existing repository URL, read from `origin`, is:

```text
https://github.com/ANSHIKAAGRAWAL1/devops.git
```

Use this repository; do not create a new `devops-sample-code` repository.

1. From the Jenkins dashboard, click **New Item**.
2. Enter `HelloWorld`, select **Freestyle project**, and click **OK**.
3. Under **Source Code Management**, select **Git**.
4. Enter `https://github.com/ANSHIKAAGRAWAL1/devops.git` as **Repository URL**. Set the branch specifier to `*/main` (or the branch containing this exercise if it is moved).
5. If Jenkins checks out the complete repository into the workspace root, the script is at `Ex 8/hello-world.sh`. Do not configure sparse checkout unless needed.
6. Under **Build Steps**, select **Execute shell** and enter:

7. Click **Save**.
8. From the job page, click **Build Now**.
9. In **Build History**, open the new build number, then open **Console Output**.

## Verify the build

The console output for a successful build should include:

```text
Hello, Jenkins!
Finished: SUCCESS
```

`Finished: SUCCESS` is produced by Jenkins only after the build step exits successfully. The repository script has been checked locally, but no Jenkins web job has been configured or run as part of this repository change.

## Repository access and credentials

The repository URL above is the actual `origin` URL. For a public repository, Jenkins can usually check it out without credentials. For a private repository, add an SSH key or narrowly scoped access token as a Jenkins credential and select that credential in the job's Git SCM configuration. Never place passwords or tokens in the Repository URL, build command, README, or shell script. Do not create a personal access token unless private-repository access requires one.

## Troubleshooting

- **Cannot connect to Jenkins:** check `docker ps -a`, then `docker logs jenkins`; wait for startup and confirm the host port mapping. Do not create a duplicate container if one already exists.
- **Git checkout fails:** confirm the repository URL and branch. For a private repository, select the correct Jenkins credential; for a public repository, try checkout without credentials.
- **Script not found:** the full-repository workspace command must `cd "Ex 8"` before running `bash hello-world.sh`. Check that Git checkout includes the committed file and that the job's configured branch contains it.
- **Bash is missing:** install/configure a Linux/Unix Jenkins agent with Bash and Git. Execute shell does not run in Windows PowerShell merely because Jenkins was opened from Windows.
- **Permission denied with `./hello-world.sh`:** on Linux, set the executable bit with `chmod +x hello-world.sh`; or use the documented `bash hello-world.sh` command, which does not require that bit.
- **Build failed:** open the build number's **Console Output**, find the first failing command, and correct that specific checkout, path, or shell issue before rebuilding.
- **Port 8080 is occupied:** inspect existing containers and host port use first. Do not delete shared Jenkins data; if configuring a separate instance, choose a free host port and browse to that mapped port.

## Cleanup

No Jenkins container was installed or started by this exercise. Keep using any pre-existing shared Jenkins instance. For an instance you created specifically for this lab, stop it to preserve its data:

```powershell
docker stop jenkins
```

Only remove a container if you personally created it for this lab, have confirmed its data is no longer needed or backed up, and intentionally want to discard it. Do not use `docker rm -v` on a shared or existing Jenkins instance; Jenkins data may be stored in the container or a volume. This exercise does not remove containers or volumes automatically.
